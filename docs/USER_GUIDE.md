# ChainBox 使用说明

## 安装

1. 从 [Releases](https://github.com/dukangalex/ChainBox/releases) 下载 **ChainBox-android.apk**。
2. 允许安装未知来源应用后安装。
3. 同一签名且 versionCode 更大的新版可直接覆盖。

设置 → 应用版本 应与 Release tag 一致（如 1.0.17）。

语言可在 **设置 → 应用 → 语言** 中选择简体中文、繁体中文、English 等；不要只留「跟随系统」时若系统是中文、界面仍大量英文，请更新到 1.0.13+。

检查更新：打开 **设置 → 应用 → 检查更新**。有新版本会弹出「下载安装 / 查看发布」；已是最新或失败也会弹窗，并可跳到 GitHub Releases。请先允许安装未知应用。

## 导入配置

1. 仪表 → 添加配置。
2. 导入机场或自建节点订阅，设为当前配置。
3. 如需跨配置串联，再导入另一份落地配置。落地不必设为当前配置。

远程订阅若含 Clash 风格 `plugin_opts` 对象，1.0.15 会在导入/刷新时自动转成 sing-box 字符串，不再报 unmarshal 错误。

## 链式代理

Chain 是 sing-box 原生 outbound：按你指定的顺序串联已有出站。不对节点规定「前置 / 中转 / 落地」以外的固定角色，也不绑定机场或协议。

**每份配置独立绑定。** 在 Kitty Network 上保存的链路不会套到 MYCF 或 edgetunne；切换配置后各自走自己的落地。

**订阅更新不会清掉链式。** 入口/落地存在本地设置里，不写进订阅 JSON。远程刷新只换节点列表，启动时再按绑定组链。若入口分组被机场改名，会自动改用当前配置的主分组，落地仍有效。

1. 把要串联的配置设为当前配置。
2. 打开 **工具 → 链式代理**。
3. **选择入口**：当前配置里的分组或节点（前置机场）。不要依赖「漏网之鱼」。
4. **选择落地**：当前配置里的另一个节点，或另一份配置里的分组/节点。落地列表按配置分组。
5. 点 **保存并绑定到「当前配置名」**。
6. 若服务已在运行会自动重载。链路为：入口 → 落地 → 目标。IP 检测网站应显示**落地**地址。

**Fail Closed**：链路或节点失败会明确报错并停止启动，不会偷偷改走 DIRECT。哪些流量走 Chain，仍由你自己的路由规则决定。

**取消链式**：只取消当前配置；其他配置的绑定保留。删除配置时会清掉相关绑定。

1.0.14 及更早内核把 hop 的 detour 接反了，出口 IP 会显示成前置机场。1.0.15 已按文档「第一个是入口、最后一个是落地」编译。
1.0.16 起绑定按配置存储，不再全局套用。
1.0.17 起订阅更新后自动沿用绑定，入口改名会回退到主分组。

## 配置覆盖

路径：**设置 → 配置覆盖**。开关只改运行时，不改订阅文件。点 ⓘ 可看说明。

配置规范化已移除：它会改写订阅的 DNS/路由/入站，容易出现 `dependency[DIRECT] not found` 等启动失败。请用订阅本身的分流，加上下面这些独立开关。

| 开关 | 作用 |
|------|------|
| 防 WebRTC 泄露 | 拦截 UDP 3478/19302/5349 |
| ECH（DNS HTTPS） | 放行 EchConfig 所需的 HTTPS/SVCB DNS 查询；节点里的 `tls.ech` 原样交给内核。默认开 |
| 中国直连 | 打包：绕过中国 IP/域名、中国公共 DNS IP/域名、局域网 IP/域名 |
| 严格路由 | TUN `strict_route` |
| DNS 防泄漏倾向 | DNS 独立缓存、自动探测网卡 |
| 禁用 IPv6 | DNS `ipv4_only`，拦截 IPv6 |
| 禁用 QUIC | 拦截 UDP 443 |
| 排除国内 QUIC | 国内域名 UDP 443 走 direct，其余仍拦 |

官方 sing-box 在 `tls.ech.enabled` 且未提供 config 时，会查 HTTPS DNS 记录获取 EchConfig。ChainBox 不再改写这段 TLS；默认打开「ECH（DNS HTTPS）」以免订阅把 HTTPS 查询拦掉。

## 备份

**设置 → 备份与恢复**。

WebDAV（含 TeraCLOUD）走 HTTPS。若 VPN 已开启，备份会尽量改走系统 Wi-Fi/蜂窝直连，避免证书被隧道干扰。

恢复会先停服务并关闭数据库，再覆盖写入，最后删掉 SQLite WAL/SHM，避免「能备份但不能恢复」。下载内容会校验 ZIP 文件头。

## 调试

**工具**页：网络质量 / STUN / 崩溃报告。

开启防 WebRTC 后，STUN 测试失败是预期（端口被拦）。测 NAT 时请临时关掉该开关。

## 常见问题

**必须卸载才能装新版**  
debug 与正式签名混过。卸载后装正式 `ChainBox-android.apk`，以后同一 keystore 可覆盖。

**点更新闪退**  
versionCode 没变大或签名不同。换正式版并且版本号递增的包。

**链式保存后无法启动，提示 unknown field fail_closed**  
内核 chain 出站只有 `outbounds` 字段。更新到 1.0.14+。

**链式保存后无法启动，提示含 DIRECT**  
入口被锁在「漏网之鱼」。更新到 1.0.13+，在链式页手动选「节点选择」等代理分组再保存。

**链式连上了但 IP 是前置机场**  
1.0.14 内核 detour 方向反了。更新到 1.0.15，保存链式后重载，再用 ippure 等检查，应显示落地 IP。

**保存链式后所有配置都变成同一条链路**  
1.0.15 把落地存在全局设置里。更新到 1.0.16，为每个配置分别保存。

**订阅一更新链式就没了，要重新配**  
旧版把 Chain 写进订阅 JSON，刷新就覆盖。1.0.17 绑定存在本地，刷新后自动组链。

**开启配置规范化后报 dependency[DIRECT] not found / EOF**  
规范化已删除。关掉该开关（1.0.16 已无此开关）后重载，使用订阅原文。

**远程更新报 plugin_opts cannot unmarshal object**  
Clash 订阅把 plugin_opts 写成了对象。1.0.15 会自动转成字符串。

**STUN 测试 EOF**  
防 WebRTC 拦截了 3478。这是防泄漏生效，不是网络坏了。

**官方有 ECH，ChainBox 用不了**  
1.0.17 默认打开放行 HTTPS DNS。节点需自带 `tls.ech.enabled`。不会给所有节点强开 ECH。

**WebDAV 连通失败：Trust anchor / 证书校验**  
1.0.16+ 会绕过 VPN 直连并使用系统信任库。请确认设备时间正确。TeraCLOUD 地址需带 `https://` 与目录尾斜杠，例如 `https://miya.teracloud.jp/dav/`。

**能备份但不能恢复**  
1.0.17 会关闭数据库并清 WAL 再覆盖。请用新版重新备份后再恢复。

**检查更新没反应 / 没有安装提示**  
1.0.14 起会弹窗；若系统拦截未知来源，会先跳到「允许安装未知应用」。也可点「查看发布」用浏览器下载 `ChainBox-android.apk`。
